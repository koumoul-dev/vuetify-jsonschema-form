# Known upstream bugs

Found while writing the doc-next documentation (2026-07-04 navigation & content redesign). None of these are doc-next issues — they live in `@json-layout/core`, `@json-layout/vocabulary`, `lib/` (`@koumoul/vjsf`), or the official plugins. Not yet filed as GitHub issues.

1. **Serializer `ucs2length` interop bug** — `@json-layout/core`'s `serialize.js` fails to unwrap Ajv's `ucs2length` runtime helper's `.default` export the way it does for `equal`, so any precompiled schema using a string `minLength`/`maxLength` throws `func1 is not a function` at render time. Worked around in doc-next by marking the two affected v2-compat demos as known-incompatible (`build/examples-layouts-plugin.ts`, `KNOWN_INCOMPATIBLE`) with an accurate on-page warning instead of running the broken demo.
2. **`doc-options.js` naming mismatch** — the generated options catalogue (`@json-layout/core/src/utils/doc-options.js`) documents `listDialogOptions`/`listMenuOptions`, but the real runtime option names are `listDialogWidth`/`listMenuWidth` (`@json-layout/core/src/state/options.js`, `lib/src/components/nodes/list.vue`). Patched locally in `src/doc-options.ts` with a comment; the upstream data should be fixed to match.
3. **Date pickers don't wire `min`/`max`** — `date-picker`/`date-time-picker`/`time-picker` derive `min`/`max` from `formatMinimum`/`formatMaximum` in `@json-layout/vocabulary`'s `normalize.js`, and that value does drive JSON Schema validation, but the Vuetify node components (`lib/src/components/nodes/`) never forward it via `layoutPropsMap`, unlike `number-field`/`slider`. Result: an out-of-range value is rejected on validation, but the calendar UI never greys out the disallowed days. Documented as observed behavior on `/components/date-time`, with `layout.props.min/max` shown as the (non-validating) UI-only workaround.
4. **`img-cropper` plugin is WIP** — `@koumoul/vjsf-img-cropper` is currently a plain file picker; its `node.vue` imports `vue-cropperjs` but never renders or opens a crop UI (`menuOpened` is never toggled). Documented on `/plugins/img-cropper` as observed behavior, not as a cropping feature.
5. **`file-input` limitations** — the `file-input` component (`lib/src/components/nodes/file-input.vue`) does not support `type: "array"` with multiple files (logs "File input doesn't support multiple inputs yet" and only keeps one file). Also, its value is the raw `File` object: it serializes to `{}` and fails a `type: "string"` schema check rather than encoding to a data URL or a `{name, size}` shape. Documented as-is on `/components/file`.
6. **`@koumoul/vjsf` hot-swap bug** — found while building the playground (live sandboxed editor): swapping the `schema`/`options` props of a mounted `<Vjsf>` in place silently drops freshly-added props instead of picking them up. Worked around in the playground with a `:key`-based remount (`src/pages/editor.vue`); the underlying lib behavior should be fixed so consumers don't need to force a remount.
