# Internationalization

## Locales

VJSF ships 4 built-in locales: `en` (default), `fr`, `nl` and `de`. The
`locale` compile option selects which one is used; `defaultLocale`
(default `en`) is the fallback used when a locale-dependent lookup (see
[translating schema content](#translating-schema-content) below) has no
entry for `locale`.

## Overridable messages

Besides the locale-dependent labels above, JSON Layout uses a small set of
its own messages internally — for buttons, confirmation dialogs, error
summaries, schema annotations, etc. Every one of them is translated in
all 4 built-in locales, and every one of them can be overwritten (see
[Overriding](#overriding) below).

<I18nMessages />

`errorOneOf` and `errorRequired` are used at compile time (baked into the
generated validation messages); the rest are used at runtime.

## Overriding

The global `messages` option lets you overwrite only the keys you want to
change, for the whole form:

```js
const options = {
  locale: 'fr',
  messages: {
    addItem: 'Ajouter un nouvel élément',
  },
}
```

`layout.messages` does the same thing for a single node and everything
under it, on top of whatever the global option already set:

```json
{
  "type": "array",
  "title": "An array",
  "layout": {
    "messages": { "addItem": "A custom addItem message" }
  },
  "items": {
    "properties": {
      "str1": { "type": "string" }
    }
  }
}
```

## Translating schema content

Locale-dependent content that lives *in the schema itself* (titles,
descriptions, etc.) is a separate concern from the messages above. VJSF
supports two mechanisms for it:

- a conventional `~$locale~` variable inside `$ref` paths, resolved by
  substituting the current locale (falling back to `defaultLocale` if
  that resolution fails). This is not part of the JSON Schema
  specification, so schemas using it become tool-specific.
- `x-i18n-*` annotations: objects keyed by locale, resolved against
  `options.locale` (falling back to `defaultLocale`) and merged over the
  annotated property. This keeps the schema valid JSON Schema for other
  tooling. It must be activated with the `xI18n` compile option (default
  `false`):

## Plugin-specific messages

Plugins can ship their own translated messages, on top of the core ones
listed above. For example the markdown plugin has its own set (editor
button labels like `bold`, `italic`, `heading`, etc.) — see
[the markdown plugin page](/plugins/markdown) for its full list and how
to override it.
